# Plan — Auth System + PostgreSQL/Drizzle Database Package

## Context

Fenr currently is a bare TanStack Start starter (demo counter/form/query page). We need:

1. A **database layer** in its own workspace package (`packages/database`) using **Drizzle ORM + PostgreSQL**, connecting to the shared local Postgres instance managed by `~/services/docker-compose.yml` (per-project role/db created via `~/services/create-project-db.sh fenr`).
2. **Authentication** via **Better Auth** integrated with TanStack Start (handler mount, cookie plugin, session helpers).
3. **Structured logging** via **Pino** (per `.agents/agents/implementer.md` contract: Pino for operational logs, no `console.log` in shipped code).
4. A new **`/auth/sign-in` page** borrowed from the `devl.dev` login block (`bunx --bun shadcn@latest add https://www.devl.dev/r/auth/login.json`) — treated as **raw material** and rebuilt per AGENTS.md (feature/domain organization, TanStack Form + Zod, hugeicons, design tokens only).

Key research findings (live docs checked):
- Better Auth v1.7.x + TanStack Start: mount catch-all `src/routes/api/auth/$.ts` using `createFileRoute('/api/auth/$')({ server: { handlers: { GET/POST } } })`; `tanstackStartCookies()` from `better-auth/tanstack-start` must be the **last** plugin.
- Drizzle adapter: `drizzleAdapter(db, { provider: "pg", schema })`; enable `advanced.database.joins: true`.
- Schema via CLI (`@better-auth/cli generate`) → output Drizzle schema into `packages/database/src/`; apply via drizzle-kit `generate` + `migrate` (committed SQL).
- Session helpers: `getSession` / `ensureSession` via `createServerFn` + `getRequestHeaders()`; routes guarded in `beforeLoad`, server fns authorized server-side only.

## Approach

### 1. Database package — `packages/database` (`@workspace/database`)
- `postgres-js` driver (`drizzle-orm/postgres-js` — works under Bun for dev SSR and prod `Bun.serve`).
- `src/index.ts`: singleton `db` + `schema` export; fails fast with clear error if `DATABASE_URL` missing.
- `src/schema/index.ts`: app schema barrel (re-exports auth tables + future app tables).
- `src/auth-schema.ts`: generated by Better Auth CLI.
- `drizzle.config.ts` + committed SQL migrations in `drizzle/`.
- Scripts: `db:generate`, `db:migrate` (run via `bun x drizzle-kit …`, Bun-only toolchain).
- Exports map so only server code imports it (`@workspace/database`).

### 2. Credentials / env
- Per-project DB created once via `~/services/create-project-db.sh fenr` → `DATABASE_URL=postgres://fenr:<pw>@localhost:5432/fenr?sslmode=disable`.
- `.env` (gitignored) holding `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` + committed `.env.example`. Location TBD (root vs `apps/web/` — see open questions; leaning `apps/web/.env` since Bun auto-loads `.env` from cwd for both `bun --bun vite dev` and `bun run start`, with drizzle.config resolving it explicitly).
- Zod-validated env parsing at server trust boundary (`src/lib/env.ts` in apps/web).

### 3. Better Auth wiring — `apps/web`
- Deps: `better-auth`, `pino`, plus `@workspace/database`.
- `src/lib/auth.ts` (server-only): `betterAuth({ database: drizzleAdapter(db, { provider: "pg", schema }), emailAndPassword: { enabled: true }, advanced: { database: { joins: true } }, plugins: [tanstackStartCookies()] /* last */ })`.
- `src/lib/auth-client.ts`: `createAuthClient()` from `better-auth/react`.
- `src/lib/session.ts`: `getSession` / `ensureSession` `createServerFn`s.
- `src/routes/api/auth/$.ts`: GET/POST → `auth.handler(request)`.
- `src/routes/auth/sign-in.tsx`: rebuilt login page (see §4); redirects to `/` when already authenticated.
- Pino: `src/lib/logger.ts` (`pino` base logger + child loggers per module, no secrets); used in auth hooks (sign-in/out events) and replaces `console.log` in `server.ts`.

### 4. Auth feature pages — rebuilt from block raw material
Block provides: split layout shell, particle-field decoration (requires PNG assets **not shipped in the registry**), fake magic-link form, OAuth buttons. Rebuild:
- Keep the split-layout aesthetic with a token-based decorative brand panel (drop particle field + missing assets).
- Real **email/password** forms via TanStack Form + Zod schemas in `src/lib/schemas/auth.ts` (`signInSchema`, `signUpSchema`) wired to `authClient.signIn.email` / `authClient.signUp.email`, with pending/error states.
- OAuth Google/Apple buttons kept as disabled visual placeholders ("coming soon").
- Shared layout/form pieces extracted under `src/features/auth/` (`auth-shell.tsx`, `oauth-buttons.tsx`, form components) — no God components; both `/auth/sign-in` and `/auth/sign-up` compose them.
- User-facing errors via `<Sonner />` toasts — specific and actionable (e.g. "Invalid email or password"), never leaking internals. Add `sonner` UI component + `<Toaster />` in `__root`.
- Missing UI primitives added via shadcn CLI into `packages/ui` (`separator`, `sonner`), lucide imports swapped to hugeicons.

## Verification
1. `bun run check` — biome + typecheck green; `bun test` green.
2. `bun run db:migrate` applies cleanly against the `fenr` database; `\dt` shows auth tables.
3. `bun run dev` → any route while signed out (`/`, `/dashboard`) redirects to `/auth/sign-in`; invalid creds → specific Sonner toast; valid creds → redirected to `/`, session cookie set, `/api/auth/get-session` returns user JSON.
4. `/auth/sign-up` creates an account (user row + credential in DB); signed-in visits to `/auth/*` bounce back to `/`.
5. Sign-out clears the session; next navigation redirects to sign-in.
6. `bun run build && bun run start` — production server boots, full loop works against `dist` output.

## Decisions (user-confirmed)
- **Sign-up**: add `/auth/sign-up` (name/email/password via `authClient.signUp.email`) reusing the same rebuilt layout.
- **OAuth**: keep Google/Apple buttons as visual placeholders (disabled, "coming soon" affordance) — no provider wiring.
- **Guarding**: the **whole app is guarded**, including `/`. Only auth pages are public. Unauthenticated navigation anywhere → automatic redirect to `/auth/sign-in`.
  - File-based routing: introduce pathless layout route `src/routes/_protected.tsx` with `beforeLoad` calling `getSession()` and `redirect({ to: "/auth/sign-in", search: { redirect: location.href } })` when no session. Existing `/` index route moves under it (`src/routes/_protected.index.tsx`); future app routes nest there too.
  - Auth pages do the inverse: `beforeLoad` redirects to `/` when a session already exists.
  - Server functions authorize via `ensureSession()` — UI guards alone are never sufficient (review-framework invariant #7).
- **Env**: `.env` lives at `apps/web/.env` (Bun auto-loads from cwd in dev + prod); committed `apps/web/.env.example`; drizzle-kit config resolves it explicitly for migrations.
